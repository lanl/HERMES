# Photon timing

New HERMES runs use the arithmetic average of all source-hit times, with no
time-walk correction. The two-stage and end-to-end examples, and configs
generated by the MCP server, use these defaults.

Set timing under
`analysis.photon_reconstruction.clustering_algorithm.settings`. The snippets
below replace only the timing fields there; keep the other clustering settings.

## Default: average time without correction

```yaml
photon_time_estimator: average
timewalk:
  method: none
```

Omitting both settings gives the same result. `average` counts every source hit,
including repeated hits at one coordinate, and gives each hit equal weight.
It does not weight hits by ToT. Fractional means are retained in the float64
`timestamp_canonical` column, within float64 precision. Times are in canonical
ticks of 25 ns / 12288, about 2.03 ps.

## Average time with calibration

```yaml
photon_time_estimator: average
timewalk:
  method: calibration
  calibration_file: calibrations/my-timewalk.json
```

Use the small correction JSON file produced by the
[time-walk calibration example](../examples/analysis/timewalk_calibration/README.md).
Paths are read relative to the directory where you start HERMES. To select the
example curve shipped with HERMES, use `calibration_file: default` instead of a
path. HERMES does not enable that curve automatically.

Calibration applies one shared linear or inverse curve to every hit according
to its raw ToT. The file uses `time_unit: canonical_ticks`; its normalized delay
is subtracted from each hit's time before calculating photon time. Calibration
aligns relative hit times but does not determine an absolute photon-arrival
offset. Separate curves for each detector pixel are not supported.

`method: calibration` requires a file. With `method: none`, omit the file or set
it to null. Blank filenames are invalid. An unusable calibration stops the run;
HERMES does not silently skip its correction. Saturated hits keep their quality
flag and use the curve at the native maximum ToT count of 1023.

## Brightest-hit time

```yaml
photon_time_estimator: brightest
timewalk:
  method: none
```

`brightest` uses the timestamp of the hit with the largest raw ToT. It returns a
time, not a ToT value. Equal-ToT hits are resolved by earliest raw time, then
source order. To correct that selected time, use the calibration block above
with `photon_time_estimator: brightest`.

## Leading-edge time and older configs

```yaml
photon_time_estimator: leading_edge
timewalk:
  method: calibration
  calibration_file: default
```

This explicitly selects the previous examples' calibrated leading-edge timing.
`leading_edge` takes the minimum hit time after optional correction, which can
change which hit is earliest. Use `method: none` and omit `calibration_file`
for uncorrected leading-edge timing.

All three estimators work with correction off or on. `mean` and `tot_weighted`
are unsupported. Timing choices do not change clustering, photon positions,
summed ToT, quality flags, or the original source-hit files.

The old `timewalk_calibration_file` setting is still accepted with a deprecation
warning and translated into `timewalk`. Newly saved records use the nested
setting. Do not supply both forms in one config. An omitted estimator now means
`average`, including in older configs; select `leading_edge` explicitly to
reproduce previous timing.

## Regenerate existing results

Before reusing completed photon results, HERMES checks their timing settings
and calibration against the requested settings. A mismatch stops the run and
preserves previous per-file results.

To regenerate photons, set this under `analysis.photon_reconstruction` while
keeping its other fields:

```yaml
runtime_options:
  overwrite: true
```

When photon and event reconstruction run together, photon overwrite also
regenerates downstream events. If you run the event stage separately, set
`analysis.event_reconstruction.runtime_options.overwrite: true` for that run.
You can also use a fresh analysis directory for the new results.
